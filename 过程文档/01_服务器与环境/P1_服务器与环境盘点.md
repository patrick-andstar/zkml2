- `ulimit -n` = **1024**（偏低，Rust 编译与 halo2 参数读写可能触顶 → 后续用 `ulimit -n 65535` 提升单会话限制）。

- 无 sudo 之外的额外能力限制；容器内 root 可写 `/root` 与 `/root/autodl-tmp`。

## 8. 结论与对计划的修正

1. **算力口径修正**：实际是 15 核 / 80 GiB / 4090D-24G，不是 `nproc` 显示的 192 核 / 1 TiB。后续所有资源预算按 **15 核 / 80 GiB / 80 G 磁盘** 计算。
2. **GPU 对本项目无直接帮助**：zkml 的 Halo2 证明器是纯 CPU（rayon 并行），4090D 不参与证明。它只可能加速 TF 侧模型导出，而导出是一次性小任务。**因此实例的"GPU 机型"几乎不影响证明耗时，CPU 核数与内存才是瓶颈。**
3. **磁盘是最紧的资源**：50 G + 30 G。KZG 参数（SRS）与 proving key 随 `k` 指数增长，必须在 P4 之前用 `estimate_size` 定出 `k` 上界。
4. **Python 必须独立环境**：conda base 3.12 + numpy 2.x 与 TF 2.12 冲突，需建 py3.11 环境。
5. **Rust 版本风险**：halo2 是 2023 年 vendored 代码（`halo2_proofs 0.2.0`），本轮装的是 2026-11-12 nightly，跨 3 年，编译失败概率不低。失败时回退到 2023 年中期的 nightly 并记录。
