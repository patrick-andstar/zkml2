## 关于服务器源码与 Git 的一致性

服务器到 GitHub 的 HTTPS 在本轮多次中断（`curl 16 HTTP2 framing layer`、`GnuTLS recv error (-110)`），
因此 `scripts/resnet18_export.py` 与 `src/utils/proving_kzg.rs` 是**经 SSH 直接写入**服务器工作区的，
不是 `git pull`。

为保证可追溯，逐文件做了 md5 校验：

| 文件 | 本地 md5 | 服务器 md5 | 一致 |
| --- | --- | --- | --- |
| `scripts/resnet18_export.py` | `2ad545475c1a8d4e3b4d856741f414db` | 同左 | ✅ |
| `src/utils/proving_kzg.rs` | `2473e0d0459e3b5735eb7e09b656cf44` | 同左（记入 manifest） | ✅ |

服务器 `git rev-parse HEAD` 停在 `85ee9a5`，与本地 HEAD 不同步；**以 md5 + manifest 为准**，不以 SHA 为准。
这一点已写入 P5 manifest 的 `proving_kzg_md5` 字段。
