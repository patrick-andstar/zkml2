# P3 ResNet18 128×128 模型与转换

> 记录时间：2026-11-15 16:00–16:06 (GMT+8)
> 结论：**完整 ResNet18（basicblock [2,2,2,2]，含全部 8 个残差连接）成功导出为 TFLite，并被 zkml 转换器完整接受，无任何降级或删层。**

## 1. 为什么需要自己写导出脚本

仓库里**没有** ResNet18 的任何定义或导出脚本（`examples/` 只有 mnist / nlp / twitter / train_graph / v2_1.0_224_truncated）。因此 P3 必须从零构造模型。新增 `scripts/resnet18_export.py`（已提交 `3448e50`）。

该脚本的三条设计约束，全部来自实测的上游限制，不是个人偏好：

| 约束 | 依据 | 处理方式 |
| --- | --- | --- |
| MaxPool 不能用 SAME padding | `python/converter.py:158` 直接 `raise NotImplementedError('SAME padding is not supported')` | 全部空间算子改为**显式 `ZeroPadding2D` + VALID** |
| 卷积只接受 NONE/RELU/RELU6 融合激活 | `valid_activations()`，且转换器**没有**独立 `RELU` 分支 | 每个 ReLU 必须被融合进 `CONV_2D` 或 `ADD` |
| 没有 BatchNorm 层 | `src/layers/` 无 BN 实现 | BN 解析式折叠进前一个卷积 |

### 关于 padding 的等价性（必须说清，否则算偷改模型）

torchvision 的 ResNet 用 `Conv2d(3,3,padding=1)` / `MaxPool2d(3,2,padding=1)`。对奇数 kernel、这几个尺寸下，`padding=1` 与 TF 的 `SAME`、与"先补 1 圈零再 VALID"三者输出尺寸与数值**完全一致**：

- `conv1`：128 + 2×3 = 134 → (134−7)/2+1 = **64**
- `maxpool`：64 + 2×1 = 66 → (66−3)/2+1 = **32**
- `stage 降采样`：32 + 2×1 = 34 → (34−3)/2+1 = **16**

所以这不是"改模型"，是**把隐式 padding 写成显式算子**。代价是图里多了 18 个 `PAD` 节点（stem 1 + 8 个 block 的 c1 + 8 个 c2 + maxpool 1），rows 略增。

### 关于 BN 折叠

BN 在推理期是仿射变换，可精确折叠：

```
W' = W · γ / sqrt(σ² + ε)          b' = β − μ · γ / sqrt(σ² + ε)
```

脚本同时构建了**两个** Keras 图：一个保留显式 `BatchNormalization`（浮点参考），一个用折叠后的 `W'`/`b'`（实际导出）。两者在同一输入上的最大绝对误差：

| 尺寸 | BN 折叠误差 | TFLite 与折叠模型误差 | argmax |
| --- | --- | --- | --- |
| 32×32 | 4.41e-06 | 2.74e-06 | 一致 |
| **128×128** | **1.10e-05** | **7.63e-06** | **一致（974）** |

误差量级就是 float32 单次运算的舍入水平，**折叠是忠实的**。

## 2. 导出的算子清单（128×128）

```
PAD              18
CONV_2D          20     1 stem + 16 block conv + 3 downsample(1×1)
ADD               8     8 个残差连接
MAX_POOL_2D       1
MEAN              1     全局平均池化
RESHAPE           1
FULLY_CONNECTED   1
```

关键点：

- **没有出现任何独立 `RELU` 节点** —— 说明 ReLU 全部被融合。block 内的 `conv+relu` 融进 `CONV_2D`；残差相加后的 ReLU 融进 `ADD`（`AddOptions.FusedActivationFunction`），而 `converter.py` 的 `_convert_add` 正好会读这个参数并传给 Rust 侧。这是本方案能成立的前提，已由算子清单证实，不是假设。
- `MEAN` 在 32×32 时**不存在**（此时特征图已塌到 1×1，GAP 退化为恒等，被 TFLite 消除），在 128×128 时存在。**不能拿 32×32 的算子清单推断 128×128。**
- 与转换器支持列表逐项核对：全部命中，无未实现算子。

### 踩过的坑：`num_randoms` 必须覆盖最大的 `batch·oh·ow`

首次用 `num_randoms=1024` 转换，Mock 在**第 1 层卷积**就 panic：

```
Random vector is too small: 4096
thread 'main' panicked at src/layers/fc/fully_connected.rs:97:
called `Option::unwrap()` on a `None` value
```

原因：RLC 实现（`implementation_idx=0`）在 `fc_rlc_vdiv_*.rs:65-66` 调用
`random_vector(constants, mm_result.shape()[0])` 和 `(..., shape()[1])`，
即**随机向量长度 = 输出张量的行数/列数**。stem 层输出 `[64, 64·64]`，需要 4096 个随机值，而只给了 1024。

修法：用上游默认的 `num_randoms=20001`。代价是行数 +18 977，可忽略。

> 这是一个**上游默认值被忽略就会炸**的隐式契约，README 未提。已记入风险表。

## 4. 输入

P4/P5 用的是**确定性随机输入**（非真实图片）：

```python
rng = np.random.default_rng(20261115)
x = rng.random((1, 128, 128, 3), dtype=np.float32)   # 值域 [0,1)
```

`input_converter.py` 按 `model_config` 里的 `inp_shapes` reshape 成 `[1,128,128,3]`（NHWC），乘以 `sf=512` 后取整为 int64。

> ⚠️ **这一版没有做 ImageNet 归一化，也没有用预训练权重。** 权重是 He 初始化的随机值。因此本轮的结论**只覆盖"结构 + 电路 + 证明"层面**，不代表任何准确率或预训练模型的数值保真。若要做预训练权重版本，需要额外的权重迁移步骤（见 P6 待办）。

## 5. 结论

- 完整 ResNet18 / batch=1 / RGB 128×128 的 TFLite 图**与 zkml 支持的算子集完全吻合**，转换零报错。
- 三项浮点保真检查（BN 折叠、TFLite 导出、argmax）均通过。
- 遗留偏差已显式声明：随机权重、无归一化、显式 PAD 替代隐式 SAME。
